O Mapa da Orientação a Objetos

Já vimos Interfaces — o contrato que faz módulos conversarem. Hoje saímos da criação de classes individuais para projetar como elas se relacionam dentro da arquitetura.

O software raramente é construído por um objeto isolado. Sistemas complexos são ecossistemas de objetos colaborando entre si. Esse vocabulário — Pedido *-- Item, Carrinho o-- Cliente — você já usa desde a Aula 04. Hoje ele ganha profundidade.
Fundamento

O Espectro dos Relacionamentos "Tem-um"

Tanto a Agregação quanto a Composição descrevem uma relação onde um objeto Todo possui instâncias de objetos Parte. A diferença arquitetural mora em duas perguntas:

01 · Ciclo de vida
Quem decide quando a Parte nasce e morre dentro da memória do sistema?
02 · Acoplamento
A Parte faz sentido existindo de forma isolada, sem o objeto pai?
Agregação

A Relação Fraca

Independência estrutural: a parte sobrevive ao todo.

  • O objeto Todo contém o objeto Parte, mas a Parte existe de forma independente no ecossistema
  • Se o objeto pai for destruído, os filhos continuam operando normalmente
Exemplo: um Carrinho de Compras (sessão web) guarda Produtos (linhas do banco de dados). Se a sessão expirar, os produtos continuam existindo no catálogo.
Do conceito ao código

Agregação na Prática

Injeção de dependência: o objeto Parte é instanciado fora e passado como parâmetro. A ligação é fraca.

Python 
class Produto:
    def __init__(self, nome):
        self.nome = nome

class Carrinho:
    def __init__(self):
        self.itens = []
    def adicionar_produto(self, produto):
        self.itens.append(produto)

celular = Produto("Smartphone")
meu_carrinho = Carrinho()
meu_carrinho.adicionar_produto(celular)
JavaScript 
class Produto {
  constructor(nome) { this.nome = nome; }
}
class Carrinho {
  constructor() { this.itens = []; }
  addProduto(produto) { this.itens.push(produto); }
}
const celular = new Produto("Smartphone");
const meuCarrinho = new Carrinho();
meuCarrinho.addProduto(celular);
Composição

A Relação Forte

Dependência estrita: uma relação de vida ou morte.

  • O objeto Todo é o responsável exclusivo e absoluto pela criação e destruição da Parte
  • Se o contêiner pai for destruído, todas as partes internas são eliminadas da memória junto
Exemplo: uma AplicacaoWeb cria seu próprio BancoDeDadosLocal internamente. Destruir a aplicação destrói o banco junto — não faz sentido um sem o outro.
Do conceito ao código

Composição na Prática

Instanciação interna: o objeto filho nasce dentro do construtor da classe pai. A aplicação controla totalmente o ciclo de vida.

Python 
class BancoDeDadosLocal:
    def conectar(self):
        return "Conectado ao DB interno."

class AplicacaoWeb:
    def __init__(self):
        self.db = BancoDeDadosLocal()
    def iniciar(self):
        print(self.db.conectar())

app = AplicacaoWeb()
JavaScript 
class BancoDeDadosLocal {
  conectar() { return "Conectado ao DB interno."; }
}
class AplicacaoWeb {
  constructor() { this.db = new BancoDeDadosLocal(); }
  iniciar() { console.log(this.db.conectar()); }
}
const app = new AplicacaoWeb();

Por que isso importa

Impacto na Engenharia de Software Real

Gerenciamento de memória
Errar na composição pode manter objetos vivos desnecessariamente — memory leaks em aplicações críticas.
Design de APIs
A agregação favorece sistemas modulares: peças trocáveis em tempo de execução sem quebrar o ecossistema.
Testes unitários
O acoplamento fraco da agregação facilita injetar mocks. Composição forte cria barreiras para testar componentes isoladamente.
Recap

Resumo do Laboratório

Agregação é colaboração
Relação fraca, objetos injetados, peças sobrevivem isoladas no sistema.
Composição é pertencimento
Relação forte, instanciados internamente, ciclo de vida unificado.
Prática universal
As regras conceituais moldam a arquitetura do mesmo jeito, em Python ou em JavaScript.

  • uma classe Carro que, no construtor, recebe um Motorista por parâmetro (agregação) e cria seu próprio Motor internamente (composição);
  • um método Carro.partir() que chama ligar() no motor e depois imprime exatamente <nome> está dirigindo;
