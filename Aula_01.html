Fundamentos

O Que É um Paradigma?

Um paradigma de programação é um modelo que define como o código deve ser estruturado e executado — não é uma linguagem, é uma forma de pensar o problema.

Existem dezenas de paradigmas na Computação, diferenciados muitas vezes por apenas um ou dois conceitos fundamentais.

Um paradigma não é o que você vê — é como você vê. Duas pessoas, o mesmo problema, soluções completamente diferentes.

A escolha

A Escolha: Orientação a Objetos

Uma mudança fundamental na organização do código: deixamos de pensar só em funções isoladas e passamos a modelar o software em Classes e Objetos que interagem entre si.

  • Foco em modelar o mundo real dentro do software
  • Base para sistemas robustos e escaláveis
  • Cada objeto tem estado (o que ele sabe) e comportamento (o que ele faz)
O par fundamental

Classes e Objetos

A classe é o molde — o projeto. O objeto é a concretização — a instância. Uma definição, infinitas possibilidades. A partir de hoje, todo exemplo aparece nas duas linguagens do laboratório: Python e JavaScript.

Python 
class Pessoa:
    def __init__(self, nome):
        self.nome = nome
    def apresentar(self):
        print(f"Olá, eu sou {self.nome}")

p = Pessoa("Ana")
p.apresentar()
JavaScript 
class Pessoa {
  constructor(nome) {
    this.nome = nome;
  }
  apresentar() {
    console.log(`Olá, eu sou ${this.nome}`);
  }
}
const p = new Pessoa("Ana");
p.apresentar();
Pilar 1

Abstração

Focar no essencial e ignorar o irrelevante. Modelar o mundo real extraindo apenas as características que importam para o problema.

Exemplo: um objeto Usuario precisa de login e senha — não da cor favorita dele.
Pilar 2

Encapsulamento

Proteção da complexidade interna. O objeto esconde como funciona e expõe apenas o necessário através de uma interface pública.

Segurança: evita que código externo quebre a lógica interna do objeto ao mexer onde não devia.
Pilar 3

Herança

Reutilização de código e lógica: construir sobre o que já existe. Hierarquias que organizam o comportamento do sistema.

A classe Filha herda os atributos e métodos da Mãe e adiciona especificidades.

Vamos usar herança com moderação mais pra frente no semestre — hoje é só o mapa.
Pilar 4

Polimorfismo

Múltiplas formas, uma única interface. Objetos diferentes respondem à mesma mensagem de maneiras distintas.

Flexibilidade para tratar tipos variados de forma uniforme — o código que chama não precisa saber qual forma exata está recebendo.

O Que Vem a Seguir

Conhecer os 4 pilares não basta — o resto do semestre é aprender a usar cada um no momento certo, e a testar se o que construímos realmente funciona.

Estrutura
Agregação e Composição — como os objetos se unem para formar sistemas maiores.
Robustez
Tratamento de Exceções — lidar com o inesperado sem derrubar o sistema.
Confiança
Testes de Software — não basta codificar, é preciso provar que funciona.
Pergunta pra pensar: se um objeto Pedido contém uma lista de Item, o que deveria acontecer com os itens se o pedido for cancelado? A resposta muda dependendo se é agregação ou composição — aula que vem.
