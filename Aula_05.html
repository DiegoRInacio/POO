A abstração é o filtro inicial: antes de herdar ou encapsular, é preciso definir a essência do objeto.
O conceito

O Filtro da Abstração

Definição: o processo de ocultar os detalhes de implementação complexos e exibir apenas as características e comportamentos essenciais para o contexto do software.

Ação-chave: ignorar o ruído corporificado no mundo físico pra focar estritamente na responsabilidade do sistema.
Engenharia

Por Que Abstração Importa

01 · Redução de complexidade cognitiva
Engenheiros não precisam entender como um motor funciona por dentro pra chamar motor.ligar().
02 · Padronização de contratos
Garante que equipes diferentes sigam a mesma estrutura fundamental ao criar novas subclasses.
03 · Prevenção de instanciação indevida
Impede criar objetos genéricos que não deveriam existir sozinhos (ex.: um Animal genérico em vez de um Cachorro).
Anatomia

Classe Abstrata × Método Abstrato

A Classe Abstrata — o molde definitivo
  • Não pode ser instanciada diretamente
  • Serve exclusivamente como base para outras classes
  • Pode conter métodos implementados e métodos abstratos
O Método Abstrato — o contrato
  • Tem assinatura, mas nenhuma implementação
  • Obriga as subclasses a fornecerem a lógica real

O Contrato em UML

A classe abstrata GatewayPagamento define o contrato; cada forma de pagamento é uma subclasse concreta que implementa processar() do seu próprio jeito.

Python

A Mecânica do Python: ABC

Python não tem a palavra-chave abstract nativa. A solução é a biblioteca padrão abc (Abstract Base Classes).

from abc import ABC, abstractmethod

class GatewayPagamento(ABC):        # herda de ABC
    @abstractmethod                 # o contrato
    def processar(self, valor):
        pass                        # nenhuma implementação aqui

class PagamentoCartao(GatewayPagamento):
    def processar(self, valor):
        print(f"Processando R$ {valor} via Cartão de Crédito.")
Tentar GatewayPagamento() gera TypeError na hora. Só PagamentoCartao() é válido — o gatilho dispara na instanciação.
JavaScript

Simulando o Contrato em JavaScript

JS moderno tem class, mas não tem classes ou métodos abstratos nativos. A engenharia simula o contrato lançando exceções.

class GatewayPagamento {
  constructor() {
    if (this.constructor === GatewayPagamento) {
      throw new Error("Classe abstrata não pode ser instanciada.");
    }
  }
  processar(valor) {
    throw new Error("Método abstrato 'processar' deve ser implementado.");
  }
}
class PagamentoPix extends GatewayPagamento {
  processar(valor) {
    console.log(`Processando R$ ${valor} via PIX.`);
  }
}
Recap

Síntese: a Arquitetura Invisível

Abstração
O filtro: só entra na classe o que o problema precisa.
Classe abstrata
O molde que ninguém instancia sozinho — só serve de base.
Método abstrato
O contrato: obriga a subclasse a implementar.
"Programe para uma interface (superclasse abstrata), não para uma implementação." — A Regra de Ouro (GoF, Erich Gamma). Se o sistema principal depende da classe abstrata, e não das concretas, ele não precisa ser reescrito quando uma forma de pagamento nova chegar.
Pratique

Sua Vez: Sistema de Alertas

Combine o que vimos hoje (abstração) com o que já sabia (agregação). Escreva o código inteiro, do zero:

  • uma classe abstrata Notificador com método abstrato enviar(mensagem) (sem implementação);
  • uma classe concreta NotificadorEmail, que herda de Notificador e implementa enviar(mensagem) imprimindo exatamente Email enviado: <mensagem>;
  • uma classe SistemaDeAlertas que agrega um Notificador recebido no construtor, com um método alertar(mensagem) que chama enviar nele;
  • crie um NotificadorEmail(), passe pra um SistemaDeAlertas, e chame alertar("Pedido confirmado").
