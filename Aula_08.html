Da Arquitetura ao Código Resiliente

Já vimos Agregação e Composição — como objetos independentes colaboram dentro de um ecossistema. Hoje mudamos de eixo: como uma classe herda comportamento de outra, e o que o sistema faz quando algo dá errado em tempo de execução.

No fluxo real de engenharia de software, a Análise mapeia o domínio do problema (o quê), e o Projeto traduz isso em arquitetura de classes (como). Herança e Tratamento de Exceções são as duas ferramentas que dão a essa arquitetura reuso e robustez — a etapa de Implementação propriamente dita.

Herança

Reuso e Hierarquia

A Herança é a manifestação direta do Projeto no código. Ela permite que uma classe (Subclasse) herde atributos e métodos de outra (Superclasse), promovendo reuso e estabelecendo relações do tipo "é um".

Superclasse · Generalização
Concentra os atributos e métodos comuns a todas as subclasses.
Subclasse · Especialização
Herda o que é comum e adiciona (ou reescreve) o que é específico.
Overriding: a capacidade de uma subclasse reescrever o comportamento herdado da superclasse quando precisa de uma versão diferente do mesmo método.
Representação visual

Herança em UML

classDiagram class EntidadeDoSistema { +atributosComuns +metodosComuns() } class Usuario { +permissoes } class Administrador { +nivelDeAcesso } EntidadeDoSistema <|-- Usuario EntidadeDoSistema <|-- Administrador

Triângulo vazado apontando para a superclasse = herança ("é um"). Usuario e Administrador são EntidadeDoSistema.

Do conceito ao código

Dissecando a Sintaxe: Herança

Python 
class Veiculo:
    def __init__(self):
        pass

class Carro(Veiculo):
    def __init__(self):
        super().__init__()

A herança é declarada entre parênteses.

JavaScript 
class Veiculo {
  constructor() {}
}
class Carro extends Veiculo {
  constructor() {
    super();
  }
}

Uso explícito da palavra-chave extends.

Tratamento de Exceções

A Rede de Segurança do Sistema

Software falha. Redes caem, usuários inserem dados inválidos. O Tratamento de Exceções é a prática de programação defensiva que impede que falhas locais causem o colapso global da aplicação.

Lançamento (throw/raise)
O sistema sinaliza que ocorreu um estado anômalo.
Propagação (bubbling)
O erro sobe pela pilha de chamadas se não for tratado.
Captura (catch/except)
O bloco de código que intercepta e resolve a falha.
Do conceito ao código

Dissecando a Sintaxe: Exceções

Python 
try:
    processar_dados()
except ValueError as e:
    log_erro(e)
finally:
    fechar_conexao()

Tipagem explícita do erro direto na cláusula de captura.

JavaScript 
try {
  processarDados();
} catch (error) {
  if (error instanceof TypeError) {
    logErro(error);
  }
} finally {
  fecharConexao();
}

Captura genérica seguida de verificação de tipo.

Síntese técnica

Exceções Customizadas em Hierarquias

O verdadeiro poder da Orientação a Objetos surge ao combinar os dois conceitos de hoje: usar Herança para criar suas próprias Exceções, construindo uma hierarquia de erros semânticos específicos para o seu negócio.

classDiagram class ErroBase { <<Exception / Error>> } class SaldoInsuficienteError { +mensagem } ErroBase <|-- SaldoInsuficienteError 
# Python
class SaldoInsuficienteError(Exception):
    pass

raise SaldoInsuficienteError()

// JavaScript
class SaldoInsuficienteError extends Error {}

throw new SaldoInsuficienteError();

Exceções customizadas transformam erros técnicos genéricos em regras de negócio compreensíveis.

Laboratório prático

O Desafio do Sistema Bancário

Você é o Engenheiro de Software responsável pelo módulo de saques de um novo banco digital. O sistema atual quebra sempre que um usuário tenta sacar mais do que tem na conta.

> Conta Corrente
> Saldo Atual: R$ 500,00
> Saque Solicitado: R$ 1000,00

> FATAL ERROR: CRASH

A missão: usar Herança para diferenciar tipos de conta e implementar Exceções Customizadas para impedir saques inválidos com graciosidade — sem derrubar o sistema.

Solução guiada

Do Diagrama ao Sistema Completo

Antes do exercício, o percurso inteiro: o diagrama de classes da solução e a implementação completa, do primeiro class ao resultado impresso no terminal.

classDiagram class ContaBase { +saldo } class ContaCorrente { +sacar(valor) } class ErroBase { <<Exception / Error>> } class SaldoInsuficienteError { +mensagem } ContaBase <|-- ContaCorrente ErroBase <|-- SaldoInsuficienteError ContaCorrente ..> SaldoInsuficienteError : lança
Python — completo 
class ContaBase:
    def __init__(self, saldo):
        self.saldo = saldo

class SaldoInsuficienteError(Exception):
    pass

class ContaCorrente(ContaBase):
    def sacar(self, valor):
        if valor > self.saldo:
            raise SaldoInsuficienteError("Saldo insuficiente")
        self.saldo -= valor

conta = ContaCorrente(500)
try:
    conta.sacar(1000)
except SaldoInsuficienteError:
    print("Erro: saldo insuficiente")
finally:
    print("Operação encerrada")
JavaScript — completo 
class ContaBase {
  constructor(saldo) {
    this.saldo = saldo;
  }
}
class SaldoInsuficienteError extends Error {}
class ContaCorrente extends ContaBase {
  sacar(valor) {
    if (valor > this.saldo) {
      throw new SaldoInsuficienteError("Saldo insuficiente");
    }
    this.saldo -= valor;
  }
}
const conta = new ContaCorrente(500);
try {
  conta.sacar(1000);
} catch (e) {
  console.log("Erro: saldo insuficiente");
} finally {
  console.log("Operação encerrada");
}

Saída em ambas: Erro: saldo insuficiente seguido de Operação encerrada.

Pratique

Sua Vez: o Saque Seguro

Escreva o código inteiro, do zero:

  • uma classe ContaBase com atributo saldo (definido no construtor);
  • uma exceção customizada SaldoInsuficienteError, herdando de Exception (Python) ou Error (JavaScript);
  • uma classe ContaCorrente que herda de ContaBase e implementa o método sacar(valor): se valor for maior que saldo, lança (raise/throw) SaldoInsuficienteError; caso contrário, subtrai valor de saldo;
  • crie conta = ContaCorrente(500) (saldo inicial 500);
  • em um bloco try/except (try/catch), tente conta.sacar(1000); no except/catch, imprima exatamente Erro: saldo insuficiente; no finally, imprima exatamente Operação encerrada.
